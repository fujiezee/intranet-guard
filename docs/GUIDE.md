# 使用指南

本指南面向使用控制台的安全值守人员和管理员。安装部署见 [README](../README.md)，试运行步骤见 [PILOT.md](PILOT.md)，
内部原理见 [ARCHITECTURE.md](ARCHITECTURE.md)。控制台中每个页面右上角的"帮助"会跳到本指南对应的章节。

<a id="quickstart"></a>
## 一、快速上手

系统由三部分组成：

| 组件 | 装在哪里 | 做什么 |
| --- | --- | --- |
| 管理中心 | 一台服务器（可多台高可用） | 控制台、存储、检测、告警推送 |
| 探针 | 每个网段一台 | 扫描资产和漏洞、运行蜜罐、读取 Suricata 流量记录 |
| Agent | 每台要保护的主机（Linux / Windows / K8s 节点） | 登录审计、命令审计、文件完整性、处置执行 |

第一次使用按这个顺序：

1. **配置告警推送**：「推送与审计 → 告警推送」添加企业微信 / 钉钉 / 飞书群机器人，点"测试"确认能收到。
2. **接入探针**：「节点管理 → 生成注册令牌」选探针，填网段名，把命令复制到该网段的一台 Linux 上执行。
3. **基线扫描**：「扫描任务 → 新建任务」选资产发现、勾选"基线扫描"，扫一遍网段，建立资产台账（不产生告警）。
4. **接入 Agent**：生成 Agent 令牌（使用次数设为主机数），把命令下发到各主机。
5. **验证检测**：「检测验证」对一台主机发起全部自检场景，全部"通过"说明检测链路正常。
6. **整理资产**：给核心系统标记重要性和负责人，为集群和跳板机建立资产组（见[资产](#assets)）。

之后日常只需要看[总览](#dashboard)和[事件](#incidents)，处理群里推送的告警。

<a id="dashboard"></a>
## 二、总览

- **未结事件**：需要优先处理的入侵线索，点击进入事件页。
- **未处理告警 / 未修复漏洞**：按级别统计。
- **风险最高的资产**：按风险分排序，鼠标悬停看扣分原因（未结事件、漏洞、高危端口、近期告警、重要性加权）。
- **最新告警**：最近产生的告警。

建议值守时先看未结事件，再看风险最高的资产。

<a id="incidents"></a>
## 三、事件

同一主机 2 小时内的入侵类告警会自动归为一个**事件**，代表一次（疑似）入侵。值守时优先处理事件，而不是逐条看告警。

- **攻击阶段**：网络攻击 → 侦察探测 → 凭据获取 → 初始访问 → 执行 → 持久化 → 防御规避 → 命令控制 → 横向移动 → 数据外传。
  涉及 **3 个及以上阶段**时自动升级为高危，几乎可以确定是真实入侵。
- **时间线**：事件中的告警，以及该主机在事件前后 30 分钟的登录、命令、文件变更记录，按时间排列，用于还原攻击过程。
- **处理**：设置状态（待处理 → 调查中 → 已解决 / 误报）和负责人，在"处置记录"中写下排查结论和已采取的措施；
  点"处置主机"直接跳到[处置](#response)。结案时事件下未处理的告警一并确认。

资产变化、漏洞等不代表入侵的告警不形成事件；root 登录、Agent 停止只在已有事件中出现时才并入。

<a id="alerts"></a>
## 四、告警

所有检测结果都会产生告警，并按推送渠道设置的级别推送到群里。

- **确认**：已知晓并处理。
- **误报**：标记误报必须填写原因（例如"授权的漏洞扫描"）。误报原因用于统计误报率和调整规则，请如实填写。
- **处置**：跳到处置页并带上告警主机和原因。
- 告警属于某个事件时显示"事件 #编号"，点击查看完整时间线。
- 标记"自检"的告警由[检测验证](#detection)产生，自动关闭，不推送。

各类告警的含义、对应的 ATT&CK 技术和处置建议见「检测验证 → 检测规则」。

<a id="assets"></a>
## 五、资产

探针扫描发现的主机和开放端口。点击一行查看详情。

- **风险分（0–100）**：用于排序，悬停可见原因。核心资产 ×1.5、重要资产 ×1.2。
- **重要性 / 负责人 / 标签**：在详情中设置。负责人会显示在总览和事件中，方便找人。
- **蜜罐**标记：该地址运行的是蜜罐，端口是伪装的。

**资产组**（右上角"资产组"）：按网段或 IP 归组，可按组筛选，并减少横向移动误报：

| 类型 | 填什么 | 效果 |
| --- | --- | --- |
| 集群 | 集群的网段，如 `10.1.0.0/24` | 组内主机互相登录不算横向移动；从组外登录多台组内主机、组内主机登录多台组外主机仍告警 |
| 运维跳板 | 堡垒机、Ansible 控制机地址 | 这些机器登录任何主机都不算横向移动 |

资产组只影响横向移动规则。跳板机本身执行了恶意命令照样告警。

<a id="tasks"></a>
## 六、扫描任务

由指定探针扫描指定目标。

- **资产发现**：只扫端口，更新资产台账；新主机、新端口、高危端口会告警。
- **漏洞检测**：扫端口后对发现的服务做检查（未授权访问、已知漏洞版本等）。
  勾选"弱口令"会对 SSH / FTP / Redis 尝试少量常见口令（每个服务最多 8 次，低于常见的账户锁定阈值）。
  **只对获得授权的资产使用弱口令检测**，并提前告知运维，避免触发其他系统的告警。
- **基线扫描**：首次扫描新网段时开启，只建立台账，不产生告警。
- 目标支持 IP、网段（`10.0.0.0/24`）、范围；端口留空使用内置的常见高危端口。
- 只扫了部分端口时，只会更新这些端口的状态，不会把其他端口标记为关闭。

<a id="vulns"></a>
## 七、漏洞

漏洞检测任务发现的问题。修复后下次扫描确认已修复，状态自动变为"已修复"。
确认不需要修复的（例如内网测试机）可以"忽略"，忽略的漏洞不计入风险分。

<a id="ids"></a>
## 八、流量检测

探针读取 Suricata 的告警（需要在探针机器上安装 Suricata 并接入镜像流量）。

- 按优先级、源 / 目的地址、规则筛选。
- **抑制**：确认某条规则在本网络中是误报（例如内部业务的特殊流量）时，抑制该规则，之后不再告警。
  抑制规则可在"抑制规则"中查看和删除。

<a id="hosts"></a>
## 九、主机审计

各主机 Agent 的状态和上报的审计记录。

- **状态**：在线、离线（3 分钟没有心跳）、已停止（Agent 主动报告停止：关机、运维停止服务）。
  非计划内的"已停止"或"离线"可能是攻击者在清除监控。
- **采集能力**：该主机实际生效的能力。Linux 上缺少"命令审计"通常是 Agent 没有以 root 运行。
- **审计记录**：登录成功 / 失败、sudo、交互式终端中执行的命令、可疑命令、文件变更、Webshell 等，可按主机、类型、来源筛选。
  K8s 节点上的命令会标明所在的 Pod。

<a id="response"></a>
## 十、处置

在主机上执行处置动作。指令通过 Agent 下发，通常一个上报周期（默认 30 秒）内完成。

| 动作 | 说明 | 撤销 |
| --- | --- | --- |
| 封禁 IP | 主机拒绝该地址的连接，到期自动解除 | 解除封禁 |
| 结束进程 | 需要填写进程号和可执行文件路径（防止误杀进程号被复用的其他进程） | — |
| 隔离文件 | 移入隔离区，保留原路径、权限和 SHA-256 | 恢复文件 |
| 隔离主机 | 只保留与管理中心、DNS 和指定地址的通信，**需要另一位管理员批准** | 解除隔离 |

- 每个动作都要填写原因，全部记入操作审计。
- 不能封禁管理中心的地址；系统目录中的文件不能隔离。
- 待执行 10 分钟没被领取（主机离线）、待批准 24 小时没批准的动作自动作废。
- Windows 上暂不支持隔离主机；K8s 中隔离的是整个节点。

<a id="intel"></a>
## 十一、威胁情报

把已知恶意的 IP、网段、域名导入后，探针在流量中、Agent 在登录来源中发现即告警。

- **情报列表 → 导入**：每行一个 IP、网段或域名，支持 `#` 注释和 hosts 文件格式；可设置级别和备注（如"演练通报"）。
- **订阅源**：填写公开情报源地址，每 6 小时自动拉取；拉取失败时保留上次的条目。
- **分析参数**：
  - 允许的域名后缀：某些安全软件会用很长的子域名查询（看起来像 DNS 隧道），在这里放行。
  - 工作时间与外传阈值：非工作时间向外传输超过阈值即告警。

流量分析（DGA 域名、DNS 隧道、C2 心跳、数据外传）需要探针读取 Suricata 完整的 `eve.json`（含 dns / tls / http / flow 记录）。

<a id="honeypot"></a>
## 十二、蜜罐

在探针上运行伪装的服务（SSH、FTP、Telnet、MySQL、Redis、HTTP 管理后台、RDP / SMB 等）。
正常业务不会访问蜜罐，**任何访问都值得关注**：告警指向访问来源，那台主机很可能已被入侵或被用于探测。

- 按探针启用，选择服务和端口。端口被占用时状态会显示原因。
- **忽略来源**：授权的漏洞扫描器等，填 IP 或网段。
- 蜜罐只记录，不提供任何真实能力；记录的密码只保留首字符。
- 建议使用对攻击者有吸引力的端口（22、3306、6379、8080），并让蜜罐地址出现在资产台账中。

<a id="detection"></a>
## 十三、检测验证

**攻击模拟自检**：在选定的主机上执行无害的模拟动作，自动核对系统是否在规定时间内告警。
用于新主机接入后的验收、升级或改配置后的回归检查。

| 场景 | 动作 | 验证的检测 |
| --- | --- | --- |
| 关键文件篡改 | 在 `/etc/cron.d` 写一个只有注释的文件 | 文件完整性 |
| 临时目录执行 | 在 `/tmp` 运行一个只会等待的程序 | 可疑进程 |
| 访问蜜罐 | 连接一个运行中的蜜罐 | 蜜罐 |
| 反弹 shell | shell 的输入输出接到本机的一个连接（不连外部、不执行命令） | 命令审计 |
| 下载并执行 | 执行含 `curl … \| sh` 字样的空操作 | 命令审计 |
| Webshell 落地 | 在网站目录写一个只有注释的 PHP 文件 | Webshell |
| 情报命中 | 查询内置的保留测试域名 | 威胁情报（需要探针看到该主机的 DNS 流量） |

- 结果：**通过**（显示检测耗时）、**失败**（超时未检测到，说明检测链路有问题，需要排查）、
  **不适用**（该主机不具备条件，例如没有网站目录、未启用命令审计）。
- 产生的文件和进程约 2 分钟后自动清理；自检告警自动关闭、不推送、不形成事件。

**检测规则**：列出所有检测规则的含义、ATT&CK 技术编号、处置建议和对应的自检场景。

<a id="nodes"></a>
## 十四、节点管理

管理探针和 Agent 的接入。

### 安装 Agent（以 Linux 服务器为例）

**前提**：目标服务器能访问管理中心的 **8443** 端口；有 root 权限（或 sudo）；系统自带的 curl 即可（7.39 及以上）。

1. **生成令牌**：「节点管理 → 生成注册令牌」，类型选 **Agent**，"使用次数"填要装的服务器数量（一个令牌可装多台），
   有效期按需（例如 24 小时），点"生成"。
2. **复制命令**：弹窗中选 Linux，点"复制命令"。命令形如：

   ```
   curl -fsSLk --pinnedpubkey 'sha256//WQcY…IPyI=' https://192.168.1.9:8443/install/agent.sh | sudo SAFE_ENROLL_TOKEN='令牌' sh
   ```

3. **在目标服务器上执行**：SSH 登录目标服务器，粘贴执行。约 10 秒完成，最后显示"safe-agent 已运行"。
4. **确认接入**：回到控制台「主机审计」，该服务器出现在列表中、状态"在线"，采集能力中有"命令审计"。

这一条命令依次做了这些事（不需要手动做任何一步）：

| 步骤 | 说明 |
| --- | --- |
| 下载安装脚本 | 从管理中心下载，并核对管理中心的公钥指纹（命令中的 `sha256//…`），防止被中间人替换 |
| 下载 Agent 程序 | 自动识别 x86_64 / ARM，下载对应程序到 `/usr/local/bin/safe-agent` |
| 注册 | 本机生成私钥（不离开本机），用令牌向管理中心换取证书；之后用证书通信，令牌从配置中删除 |
| 安装为系统服务 | 创建并启动 `safe-agent` 服务（开机自启，限制 CPU 20%、内存 256M） |

**批量安装**：同一条命令可以在多台服务器上执行（不超过令牌的使用次数），可通过 Ansible、堡垒机批量执行等现有工具下发。
主机名会作为 Agent 名称，重名时在命令中加 `SAFE_AGENT_ID='名称'`（写在 `SAFE_ENROLL_TOKEN=…` 旁边）。

**Windows**：弹窗中选 Windows，以管理员身份打开 **Windows PowerShell**（5.1，不是 PowerShell 7）粘贴执行，自动开启安全审计并安装为系统服务。

**Kubernetes**：弹窗中选 Kubernetes，在能执行 kubectl 的机器上执行三行命令，每个节点自动部署一个 Agent（包括以后新加的节点）。

**升级**：在服务器上再执行一次同一条命令（令牌过期也没关系，已注册的主机不需要令牌）。
**卸载**：把命令末尾的 `sh` 前加上 `SAFE_ACTION=uninstall`，即 `… | sudo SAFE_ACTION=uninstall sh`。
**无法联网下载 / curl 太旧**：见安装脚本开头说明的离线安装方式。

### 令牌与证书

- **生成注册令牌**：选择类型、使用次数（一个令牌可装多台）、有效期。生成后页面给出安装命令：
  - Linux：一行 `curl … | sudo … sh`，以 root 执行；
  - Windows：管理员身份打开 Windows PowerShell（5.1）粘贴执行；
  - Kubernetes：三行 `kubectl` 命令，为每个节点部署一个 Agent（DaemonSet）。
- 命令中固定了管理中心的公钥指纹，中间人无法替换下载内容。curl 太旧（如 CentOS 7）的系统可离线安装，见安装脚本开头的说明。
- 节点注册后使用证书认证，自动续期；令牌只用于首次注册。
- **吊销**：节点下线或怀疑被盗用时吊销其证书，之后该节点无法再连接。
- 升级节点：再次执行同一条安装命令即可（不需要令牌）。

<a id="users"></a>
## 十五、用户管理

- **管理员**：可以做所有操作（扫描、处置、配置、管理用户）。
- **只读**：只能查看，适合给领导、审计人员或其他团队。
- 密码至少 10 位。连续登录失败会被暂时限制。建议每位值守人员使用自己的账户，便于审计和"两人审批"。

<a id="settings"></a>
## 十六、推送与审计

**告警推送**：支持企业微信、钉钉、飞书群机器人和通用 Webhook。

- **推送级别**：只推送该级别及以上的告警。建议值守群推送"中"及以上，领导群只推"高"。
- 钉钉 / 飞书开启了"加签"时填写密钥。保存后地址会部分隐藏，密钥不再显示。
- 添加后点"测试"确认能收到。"最近状态"显示最后一次推送是否成功。
- 每条告警只推送一次；管理中心多实例切换时可能有个别重复，不会漏推。

**操作审计**：所有管理操作（登录、扫描、处置、批准、配置变更、误报标记等）都有记录，可按用户和操作类型筛选。

<a id="deploy"></a>
## 十七、部署与运维

- **备份**：一键安装已配置每日备份（数据库、CA、配置）。**CA 私钥（pki 目录）丢失后所有节点需要重新注册**，请把备份复制到其他机器。
- **升级**：用新的安装包再次执行 `sudo ./install.sh`，数据和配置保留。
- **规模**：SQLite 只适合小规模试用和单实例；正式部署请使用 PostgreSQL + ClickHouse（`-db`、`-events-db`），压测结果见 ARCHITECTURE.md 第 20 节。
- **高可用**：多个管理中心实例共用数据库，复制 pki 目录，启动参数加 `-node-urls`。节点自动在实例间切换，
  后台任务自动选一个实例执行。步骤见 README"高可用部署"。
- **Kubernetes**：管理中心不要和 Ingress（如 k3s 自带的 Traefik）装在同一台机器上，二者会争用 443 端口。

<a id="faq"></a>
## 十八、常见问题

**Agent 显示离线**：检查主机是否关机、Agent 服务是否运行（`systemctl status safe-agent`）、能否访问管理中心的 8443 端口。

**命令审计不可用**：Linux 上 Agent 需要以 root 运行；容器中运行时需要特权模式（K8s 安装清单已配置）。

**自检失败**：先看自检的"详情"。"超时未检测到"时，检查该主机 Agent 是否在线、采集能力是否完整；
"访问蜜罐"失败检查蜜罐是否在运行；"情报命中"失败检查探针是否能看到该主机的 DNS 流量。

**横向移动误报多**：为集群和跳板机建立资产组（见[资产](#assets)）。

**某条 IDS 规则一直误报**：在流量检测中抑制该规则，填写原因。

**收不到推送**：在「推送与审计」点"测试"，查看"最近状态"中的错误；确认管理中心能访问机器人地址（内网可能需要代理）。

**安装命令下载失败**：确认目标机器能访问管理中心的 8443 端口，且中间没有会解密 HTTPS 的设备（会导致公钥指纹不匹配）。
