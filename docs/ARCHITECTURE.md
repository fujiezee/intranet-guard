# 内网防护系统 架构设计

## 1. 目标

面向大型企业、多网段内网，提供四类能力：

| 能力 | 说明 | 实现组件 |
| --- | --- | --- |
| 资产发现与管理 | 主动扫描各网段主机、端口、服务，追踪新增 / 消失资产 | 网络探针 + 管理中心 |
| 流量监测与入侵检测 | 镜像流量分析，检测扫描、爆破、横向移动、异常外联 | 网络探针（集成 Suricata）+ 告警引擎 |
| 主机日志审计 | 登录、进程、文件完整性、账号变更等日志采集与告警 | 主机 Agent + 日志存储 |
| 漏洞扫描与弱口令检测 | 基于资产指纹做漏洞匹配、弱口令探测、基线检查 | 网络探针 + 漏洞库 |

## 2. 总体架构

```

                    │                                                                │
  浏览器 ── HTTPS ──▶│  Web 控制台 (Vue3)                                             │
                    │        │                                                       │
                    │        ▼                                                       │
                    │  管理中心 safe-server (Go)                                     │
                    │   ├─ API / 认证 / RBAC                                         │

                    │   ├─ 资产库        ── PostgreSQL（开发环境用 SQLite）          │
                    │   ├─ 告警引擎 / 规则 ── 关联分析、去重、通知                   │

   ┌──────┴──────┐    ┌──────┴──────┐        ┌──────┴──────┐
```

### 关键设计决策

1. **探针按网段部署，主动外连管理中心**。探针轮询领取任务、上报结果，管理中心不需要能访问每个网段，只需开放一个入站端口。
2. **IDS 不重复造轮子**：流量检测集成 Suricata（规则生态成熟），探针负责读取它的 EVE JSON 输出、归一化后上报。自研部分集中在资产关联和告警关联分析上。
3. **存储分层**：资产、任务、配置这类关系型数据放 PostgreSQL；日志、流量事件这类海量时序数据放 ClickHouse。
4. **单一二进制分发**：server / probe / agent 都编译成静态二进制，方便在大量机器上部署和升级。

## 5. 告警规则（阶段 2）

| 类型 | 触发条件 | 级别 |
| --- | --- | --- |
| new_asset | 首次发现的主机 | 中 |
| new_port | 已知主机上新开放的端口 | 低 |
| risky_port | 新开放的高危端口（telnet、redis、docker API、数据库、RDP、SMB 等） | 高 / 中 |

- 只对"变化"告警，状态不变的重复扫描不会重复告警。
- 新网段第一次扫描用**基线任务**（`baseline: true`），只建台账不告警，避免首次扫描产生大量噪音。

## 6. 主机 Agent（阶段 3）

**采集**（每 30 秒一轮，上报成功后才提交读取位置，断网恢复后补报，不丢不重）：

| 采集项 | 来源 | 说明 |
| --- | --- | --- |
| SSH 登录成功 / 失败 | `/var/log/auth.log`、`/var/log/secure`，都没有则 journald | 兼容 rsyslog 的 `message repeated N times`、OpenSSH 9.8+ 的 `sshd-session`；处理日志轮转 |
| sudo 命令 | 同上 | |
| 文件完整性 | SHA-256 指纹 | passwd/shadow/sudoers、authorized_keys、cron、ld.so.preload、pam.d、systemd 等；首轮只建基线 |
| 可疑进程 | `/proc` | 从 /tmp、/var/tmp、/dev/shm 运行，或可执行文件已被删除；同一进程只报一次 |

**检测规则**（管理中心执行，告警关联到主机 IP，即资产库中的同一资产）：

| 告警 | 条件 | 级别 |
| --- | --- | --- |
| ssh_bruteforce | 同一来源 5 分钟内失败登录 ≥ 10 次 | 高 |
| bruteforce_success | 1 小时内有过爆破的来源随后登录成功 | 高 |
| root_login | root 远程登录成功 | 中 |
| file_changed | 受监控文件新增 / 修改 / 删除 / 权限变化（账号、权限、持久化相关文件为高） | 高 / 中 |
| suspicious_process | 临时目录运行为高；可执行文件已删除为中（软件升级未重启也会出现） | 高 / 中 |
| agent_offline | 3 分钟无心跳（宕机、断网或 Agent 被攻击者停止） | 中 |

持续性行为（爆破、root 登录）按来源去重，30 分钟内只告警一次。主机事件保留 90 天。

## 7. 流量入侵检测（阶段 4）

```
交换机镜像口 ──▶ Suricata ──eve-alert.json──▶ safe-probe ──▶ 管理中心
                  (ET Open 规则)              读取、归一化       存储、关联资产、去重、抑制、告警
```

- 检测本身交给 Suricata；探针只读取 alert 类型事件（配置见 `deploy/suricata-eve.yaml`），不传输载荷。
- **分级**：Suricata 优先级 1 → 高危告警，2 → 中危告警，3 及以下只记录事件（多为策略 / 信息类规则，噪音大）。
- **资产关联**：优先关联资产库中已有的目的 / 源地址，其次内网地址；资产是被攻击方时记录受攻击端口。
- **去重**：同一规则 + 源 + 目的 30 分钟内只告警一次。
- **抑制规则**：管理员可按规则 ID（可选限定源 IP）抑制误报；被抑制的事件照常记录，只是不告警。
- IDS 事件保留 90 天。

## 8. 漏洞检测（阶段 5）

扫描任务分两类：**资产发现**（端口扫描）和**漏洞检测**（端口扫描 + 对开放端口执行检查）。

| 检查 | 方式 | 级别 |
| --- | --- | --- |
| Redis / Elasticsearch / Docker API 未授权访问 | 探针发送只读请求（INFO、GET /、GET /version） | 高 |
| Memcached 未授权访问 | `stats` | 中 |
| FTP 匿名登录 | anonymous 登录 | 中 |
| SSH / FTP / Redis 弱口令 | 需在任务中单独开启；每服务 ≤ 8 组口令，低于爆破告警阈值，尝试间隔 300ms，遇到网络错误立即停止 | 高 |
| 已知版本漏洞 | 管理中心对已采集 Banner 匹配规则，每次扫描都执行，不需要额外探测 | 按规则 |

- 检查按端口号或识别出的服务名分派，非标准端口上的 Redis 等不发送 Banner 的服务暂时识别不到。
- 版本规则只收录 Banner 能可靠识别的：OpenSSH regreSSHion（CVE-2024-6387，标为中危：发行版常回移植补丁而不改版本号）、
  vsftpd 2.3.4 后门（CVE-2011-2523）、ProFTPD 1.3.5 mod_copy（CVE-2015-3306）。规则在 `internal/vuln/banner.go`，可按需扩充。
- 弱口令检测结果只保存密码首字符和长度（如 `a****`），不保存可用口令。
- **生命周期**：发现 → 未修复（告警）；复查通过或端口关闭 → 自动标记已修复；修复后再次发现 → 重新打开（告警"漏洞复发"）；
  管理员可"忽略"已确认可接受的风险，忽略后再次发现不告警。
- 不做：通用 CVE 库匹配、Web 漏洞扫描、利用验证。需要时建议对接专业扫描器，把结果导入漏洞表。

## 9. 节点认证（阶段 6a）

```
控制台 :8080 (HTTP/反向代理)            节点接入 :8443 (mTLS，服务端证书由内部 CA 签发)
  └─ 管理员生成注册令牌 ─────────▶ 令牌 = 随机密钥.CA指纹 ─▶ 节点首次启动
                                                             1. 取 CA，用令牌中的指纹校验（防中间人）
                                                             2. 本地生成私钥 + CSR（私钥不出本机）
                                                             3. POST /enroll {令牌, CSR} → 证书
                                                             4. 之后所有请求用客户端证书
```

- **身份绑定**：证书 CN = 节点 ID，OU = 节点类型（probe / agent），由管理中心决定，不信任 CSR 内容。
  Agent 只能以自己的 ID 上报；探针只能领取、上报自己的任务；Agent 证书不能访问探针接口。
- **注册令牌**：可设可用次数（批量部署用）和有效期（≤ 30 天）；数据库只存哈希。已注册且未吊销的 ID 不能再次注册，防止用新证书顶替现有节点。
- **吊销**：管理员吊销后立即生效（每个请求都核对数据库中的节点状态和证书序列号，不依赖 CRL）。吊销后可用新令牌重新注册。
- **续期**：证书有效期 1 年，剩余不足 30 天时节点自动换发，旧证书立即失效。
- **CA 私钥**：`pki/ca.key`（0600），务必备份并限制访问；丢失后所有节点需要重新注册。
- **旧版共享 token**：设置 `SAFE_PROBE_TOKEN` / `SAFE_AGENT_TOKEN` 时控制台端口仍接受 token 认证（启动时警告），仅用于迁移，迁移完成后应删除。

## 10. 存储（阶段 6b）

- **双后端**：`-db` 为文件路径时用 SQLite（开发、几十台规模），为 `postgres://` 连接串时用 PostgreSQL（生产）。
  业务 SQL 统一用 `?` 占位符书写，执行时按方言改写；建表语句从同一份定义生成，避免两套 schema 漂移。
- **多实例并发安全**：以下操作改为单条原子语句，多个管理中心实例共用一个 PostgreSQL 时也不会重复或超额：
  - 领取扫描任务：`UPDATE … WHERE status='pending' RETURNING`，同一任务只会被一个探针请求领到；
  - 注册令牌计次：`UPDATE … SET uses=uses+1 WHERE uses<max_uses RETURNING`，并发注册不超出次数；
  - 同一节点 ID 并发注册：`INSERT … ON CONFLICT DO UPDATE WHERE status<>'active'`，只有一个成功；
  - Agent 离线判定：`UPDATE … WHERE status='online' RETURNING`，每次离线只告警一次。
- **迁移**：`safe-server -migrate-from safe.db -db postgres://…` 在一个事务里复制全部数据并重置自增序列；目标库非空时拒绝执行。
- **测试**：`make test` 跑 SQLite，`make test-pg` 在 PostgreSQL 上跑同一套测试（含并发测试）。

## 11. 事件存储（阶段 6c）

主机事件和 IDS 事件是数据量最大的部分，通过 `store.EventStore` 接口与业务数据分离：

- 默认存在主库（SQLite / PostgreSQL），由每小时的清理任务删除 90 天前的数据。
- 加 `-events-db clickhouse://user:pass@host:8123/safe` 后存到 ClickHouse：按月分区，排序键针对爆破检测
  （agent_id, type, src_ip, ts）优化，过期由表 TTL 自动清理。资产、告警、漏洞等业务数据仍在主库。
- 写入顺序：事件先写事件存储，再在主库事务里更新状态和生成告警。后一步失败时节点会重报，
  事件可能多存一份（至少一次语义），告警由去重键保证不重复。
- 已知限制：切换到 ClickHouse 不会迁移主库中已有的历史事件；SQLite → PostgreSQL 迁移命令只迁移主库。

## 12. 告警推送与审计（阶段 7）

- **推送**：每 10 秒把新告警按渠道的最低级别过滤后合并成一条消息发送；支持钉钉 / 飞书加签，
  检查机器人返回的业务错误码（关键词、签名、IP 白名单配置错误时 HTTP 仍是 200）。推送进度存在数据库中，
  多实例部署时用比较并交换保证同一告警只推送一次（先占位再发送：发送失败重试一次后放弃，告警仍可在控制台查看）。
  渠道列表接口对 Webhook 令牌脱敏，不返回加签密钥。
- **审计**：登录（含失败与锁定）、退出、改密码、用户增删、下发任务、确认告警、漏洞状态、IDS 抑制、节点吊销、
  注册令牌、推送渠道等操作写入 audit_log，记录操作人、对象、详情、来源 IP、成功与否，仅管理员可查。
- **任务超时**：执行超过 `-task-timeout`（默认 6 小时）仍未上报结果的任务标记为失败；之后迟到的结果照常接收。

## 13. 蜜罐与攻击模拟自检（v0.2）

**蜜罐**运行在探针上（`internal/honeypot`），由控制台按探针配置，探针每 15 秒拉取配置并上报各端口监听状态。

- 伪装服务：SSH（记录密码 / 公钥尝试）、FTP、Telnet、MySQL（握手后取用户名）、Redis（记录 AUTH 和命令，如 `CONFIG SET dir`）、
  HTTP 管理后台登录页、通用 TCP（RDP / SMB 等只记录首包）。一律拒绝登录，不提供任何真实能力。
- 告警关联到**访问来源**（很可能已失陷），高危，同来源同服务 30 分钟内去重。密码只保留首字符。
- 不告警：探针本机地址（自己的扫描任务）、配置的忽略来源（如授权扫描器）；单个来源每分钟最多 30 条事件。
- 蜜罐地址上的伪装端口不产生资产变化告警，资产页标识为蜜罐。

**攻击模拟自检**（`internal/simulate`、`internal/agent/simulate.go`）验证检测链路真实有效：

```
控制台下发 → Agent 上报时在回复中领取指令 → 执行预定义的无害动作（产物带编号 sim-xxxxxxxx）
          → 正常检测链路产生告警 → 告警内容含已登记的编号 → 自检通过，告警自动关闭且不推送
          → 超时未出现告警 → 自检失败（检测能力有问题）
```

| 场景 | 动作 | 验证的规则 |
| --- | --- | --- |
| 关键文件篡改 | 在 /etc/cron.d 写入只含注释的文件，2 分钟后删除 | 文件完整性 |
| 临时目录执行 | 复制系统 sleep 到 /tmp 运行，2 分钟后结束并删除 | 可疑进程 |
| 访问蜜罐 | 连接一个正在监听的蜜罐端口并发送自检标记 | 蜜罐 |

Agent 只接受这三种预定义动作，不执行服务端下发的任意命令。所有检测规则登记在 `internal/alert/catalog.go`
（ATT&CK 技术编号、处置建议、对应的自检场景），控制台"检测验证"页可查看覆盖情况。告警可标记为误报并填写原因，用于统计误报率。

## 14. 主机检测深化（v0.3）

**命令审计**（`internal/agent/procmon_linux.go`）：使用内核进程连接器（netlink proc connector，2.6.15 起支持，
CentOS 7 也可用）接收每次 exec，再从 `/proc` 读取命令行、用户、父进程、终端和标准输入输出。不依赖 eBPF 和编译工具链；
代价是执行后立即退出的极短命进程可能读不到命令行。需要 root，未启用时控制台在主机上标注"无命令审计"。

- 交互式终端（有 TTY）中的命令作为审计记录上报（不告警）；所有执行都经过检测规则（`cmdrules.go`）：

| 规则 | 判断方式 | 级别 |
| --- | --- | --- |
| 反弹 shell | shell 的标准输入或输出是 **TCP** 连接（在进程的网络命名空间按套接字 inode 查 `/proc/<pid>/net/tcp`）；`ssh host 命令` 用本地套接字，不会误报 | 高 |
| 反弹 shell 命令 | `/dev/tcp/`、`nc -e`、`socat exec:`、mkfifo + nc、python / perl / php / ruby 套接字一行代码 | 高 |
| 下载并执行 | `curl/wget … \| sh`、下载后 chmod +x 执行、`base64 -d \| sh` | 高 |
| Web 服务派生命令 | nginx / httpd / apache2 / php-fpm 等直接启动 shell 或侦察命令（Webshell 迹象） | 高 |
| 应用服务派生 shell | java / node / uwsgi 等启动 shell（有合法场景） | 中 |
| 挖矿 / 清除痕迹 | `stratum+tcp://`、xmrig；`history -c`、清空 auth.log 等 | 高 / 中 |

- 相同规则 + 命令 60 秒内只上报一次；缓冲区 5000 条，上报失败时保留重试，溢出时上报丢弃数量。
- 管理中心对相同主机的相同命令 30 分钟内只告警一次。

**Webshell 监控**：递归扫描网站目录（默认 /var/www、/usr/share/nginx/html、/srv/www、Tomcat webapps，`-web-dirs` 可改）
中的 .php / .jsp / .asp 等脚本，按大小和修改时间发现新增或修改，只对变化的文件检查特征（eval、编码混淆、命令执行等）。

**横向移动**：同一内网来源 10 分钟内成功登录 5 台以上主机，告警关联到来源。跳板机等合法场景可标记误报。

**Agent 停止**：收到停止信号（systemctl stop、关机）时最后上报一次，状态为"已停止"并告警（中），不再触发"离线"告警；
被 kill -9 或断网则仍按 3 分钟无心跳判为离线。

**资源上限**：Agent 的 systemd 单元限制 CPU 20%、内存 256M、低优先级与空闲 IO。

**新增自检场景**：反弹 shell（shell 输入输出连到 Agent 在本机建立的 TCP 连接）、下载并执行（含 `curl … | sh` 字样的空操作命令）、
Webshell 落地（只含注释的 PHP 文件）。均为无害动作，2 分钟后清理。

## 15. 响应处置（v0.4）

管理员在控制台发起，指令随 Agent 上报的回复下发（与自检相同的通道，mTLS 双向认证），5 分钟内有效，过期不执行。

| 动作 | 实现 | 撤销 | 审批 |
| --- | --- | --- | --- |
| 封禁 IP | nftables 独立表 `inet safe_block` 的集合，带到期时间由内核自动解除；无 nft 的老系统回退 iptables（到期由 Agent 定时解除） | 解除封禁 | 否 |
| 结束进程 | 先核对 `/proc/<pid>/exe` 与发起时一致，防止 PID 被复用后误杀 | — | 否 |
| 隔离文件 | 复制到 Agent 状态目录下的隔离区（权限 600，记录原路径、权限、SHA-256）后删除原文件；系统目录（计划任务目录除外）禁止 | 恢复文件（原位置已有文件时不覆盖） | 否 |
| 隔离主机 | nftables 独立表 `inet safe_isolate`：只允许回环、管理中心、DNS 和指定地址，其余（含已建立的连接、转发）全部丢弃 | 解除隔离 | **需要另一位管理员批准** |

- 安全约束：不能封禁管理中心地址（Agent 侧检查，否则无法再接收解除指令）；无法解析管理中心地址时拒绝隔离；
  所有动作、批准、撤销进审计。待执行 10 分钟未领取、待批准 24 小时未批准的动作自动作废。
- 不改动系统已有的防火墙规则（使用独立的 nftables 表），解除时只删除自己的表或集合元素。
- 端到端测试中，隔离在 CI 机器上的独立网络命名空间里对第二个 Agent 真实执行，验证隔离后其他地址不可达、
  与管理中心保持通信、解除后恢复。

## 16. 事件、攻击链与资产风险（v0.5）

**事件**：同一主机（告警关联的 IP）2 小时内的入侵类告警自动并入同一个未结事件，否则开启新事件。

- 告警按攻击阶段归类（`internal/alert/stages.go`）：网络攻击（IDS）→ 侦察探测（蜜罐）→ 凭据获取（爆破）→ 初始访问
  （爆破成功、root 登录）→ 执行（可疑命令 / 进程）→ 持久化（文件篡改、Webshell）→ 防御规避（Agent 停止 / 离线）→ 横向移动。
- 资产变化、漏洞等"卫生"类告警不形成事件；root 登录、Agent 停止 / 离线多为运维操作，只并入已有事件，不单独开启。
- 级别取所含告警的最高级别；**涉及 3 个及以上阶段时升级为高危**（多阶段几乎可以确定是真实入侵）。
- 攻击模拟自检产生的告警不进入事件。
- 详情包含按时间排列的告警，以及该主机在事件前后 30 分钟内的审计记录（登录、命令、文件变更等），
  可设置状态（待处理 / 调查中 / 已解决 / 误报）、负责人、处置记录；结案时其下未处理的告警一并确认。

**资产风险分**（0–100，用于排序）：未结高 / 中危事件各 +40 / +20，未修复高 / 中危漏洞各 +30 / +10，
开放高危 / 敏感端口各 +10 / +5，近 7 天未处理告警最多 +30；重要资产 ×1.2、核心资产 ×1.5。每项扣分都列出原因。
资产可设置重要性、负责人、标签。

## 17. Windows Agent 与域控检测（v0.6）

同一个 `safe-agent` 程序编译为 Windows 版本，作为服务以 LocalSystem 运行。数据来源是 Windows 事件日志：
通过 `wevtapi.dll` 读取 Security 与 System 日志，渲染为 XML 后解析（字段名与系统语言、代码页无关），
用书签直接定位到上次处理的记录，不从日志开头扫描。生成的事件与命令审计共用缓冲区，上报失败时保留重试。

| 事件 | 转换为 | 说明 |
| --- | --- | --- |
| 4625 登录失败 | 登录失败 | 接入现有的暴力破解检测 |
| 4624 登录成功 | 登录成功 | 只上报远程桌面和 NTLM 网络登录（Kerberos 网络登录是域内正常流量）；LogonType 9（seclogo）为疑似凭据传递 |
| 4688 进程创建 | 可疑命令 | Windows 命令规则（`winrules.go`）：编码的 PowerShell（解码后再检查）、下载执行、系统程序代理执行、删除卷影副本、清除日志、凭据窃取、Web / 数据库 / Office 进程派生命令 |
| 4720 / 4728 / 4732 / 4756 | 账户变更 | 新建账户（中）；加入特权组（高，按 SID 识别，与语言无关） |
| 1102、System 104 | 可疑命令 | 事件日志被清除 |
| System 7045 | 可疑命令 / 审计记录 | 新安装服务：PsExec、cmd / PowerShell 启动、程序在临时目录等为高，其余只记录 |
| 4769 | 域攻击 | Kerberoasting：同一账户 10 分钟内以 RC4 请求 3 个以上服务票据 |
| 4768 | 域攻击 | AS-REP Roasting：未启用预身份验证的账户被请求 TGT |
| 4662 | 域攻击 | DCSync：非域控账户请求目录复制权限 |

- 一键安装（`/install/agent.ps1`，Windows PowerShell 5.1）：命令先用 `ServicePointManager` 回调固定管理中心公钥
  （证书原始公钥加 P-256 前缀后的 SHA-256，与 `curl --pinnedpubkey` 相同，有单元测试保证），再下载脚本；
  脚本按子类别 GUID 开启所需审计、启用进程命令行记录、安全日志不足 256MB 时扩容，注册后安装服务并设置失败自动重启，
  状态目录（含节点私钥）只允许 SYSTEM 与 Administrators 访问。域组策略中的高级审核策略会覆盖本地设置。
- 处置：封禁 IP 使用 Windows 防火墙规则（`safe-block <IP>`，到期时间记录在状态目录，由 Agent 解除）；
  结束进程核对 `QueryFullProcessImageName`（不区分大小写）；隔离文件禁止系统和程序目录。**隔离主机暂不支持**：
  需要修改整机防火墙默认策略，恢复不当会导致无法远程登录，返回明确的失败原因。
- 自检：下载并执行（PowerShell 注释形式的空操作）、Webshell 落地（IIS 网站目录）可用；其余场景报告“不适用”。
- 验证：CI 在 GitHub 的 Windows Server 上真实安装并制造事件；域控规则只有样例事件的单元测试，需要在测试域中验证。

## 18. 威胁情报与外联分析（v0.7）

探针除告警外还读取 Suricata eve.json 中的 dns / tls / http / flow 记录，在本地分析（`internal/netintel`），只上报结果；
原始记录量很大，不传给管理中心。分析结果的告警关联到内网中的相关主机，归入"命令控制"或"数据外传"阶段。

| 检测 | 判断方式 | 级别 |
| --- | --- | --- |
| 情报命中 | DNS 查询、TLS SNI、HTTP Host 按域名后缀匹配；连接两端按 IP / 网段匹配（内网主机访问或被访问） | 按情报 |
| DGA | 同一主机 10 分钟内 10 个以上"随机外观且不存在"（NXDOMAIN）的域名；能解析的 CDN 随机子域名不计入 | 高 |
| DNS 隧道 | 同一主机 10 分钟内对同一注册域名查询 50 个以上、子域名平均 30 字符以上的不同名字；可配置允许列表 | 高 |
| C2 心跳 | 2 小时内对同一外部地址:端口 12 次以上连接，间隔 10 秒至 1 小时，去掉两端各 10% 后变异系数 ≤ 0.2；排除 DNS / NTP | 中，目标在情报中为高 |
| 数据外传 | 非工作时间（默认 22:00–07:00，探针本地时区）单台主机 1 小时内外发超过阈值（默认 1 GB） | 中 |

- 情报：手工导入（每行一个 IP / 网段 / 域名，兼容 hosts 文件与 CSV 第一列；内网地址、回环地址和小于 /8 的网段被忽略）和订阅源
  （管理中心每 6 小时拉取，失败时保留旧条目；默认没有订阅源，需要管理中心能访问外网）。情报有版本号，
  探针在拉取配置（每 15 秒）时发现版本变化即重新拉取完整列表。
- 管理中心侧同时用情报核对 Agent 上报的登录来源（成功为高、失败为中）和 IDS 告警的对端地址。
- 内置自检域名 `safe-sim.example.com`（保留域名）：“情报命中”自检让 Agent 查询带自检编号的子域名，
  验证探针能看到这台主机的 DNS 流量。探针看不到时自检超时失败，说明 DNS 不在监控范围。
- 内外网判断使用 RFC 1918、CGNAT、ULA 等私有地址段；内网使用公网地址段的单位需要后续支持自定义内网网段。
- 探针安装时优先读取完整的 `eve.json`；只有 `eve-alert.json` 时网络分析不可用。
- 局限：新注册域名检测需要外部数据，未实现；文件哈希情报需要 Agent 计算可执行文件哈希，未实现；
  CI 中没有 Suricata，端到端测试用按 Suricata 格式写入的记录验证探针读取之后的链路。

## 19. 资产组与集群

资产组按 IP / 网段归组（`internal/store/groups.go`），资产列表显示所属组并可按组筛选。两种类型：

- **集群**：成员之间互相登录属于正常（Hadoop、数据库主从、K8s 节点、Ansible 管理的同一批机器）。
  横向移动统计时，来源与目标同属一个集群的登录不计入；集群成员登录集群外的主机、集群外来源登录多台成员仍照常告警。
- **运维跳板**：成员（堡垒机、自动化运维机）登录任何主机都不计入横向移动。

资产组只影响横向移动这一条规则，不影响爆破、可疑命令等其他检测：跳板机本身被攻破后执行的恶意命令照常告警。

## 20. 权限模型

| 角色 | 权限 |
| --- | --- |
| admin | 全部：下发任务、确认告警、管理用户 |
| viewer | 只读：查看总览、资产、任务、告警 |

- 密码 bcrypt 存储，至少 10 位；会话 token 只存 SHA-256 哈希，有效期 12 小时。
- 同一 IP 连续 5 次登录失败锁定 5 分钟；用户名不存在时同样执行 bcrypt，防止计时枚举。
- 修改密码 / 删除用户会让其全部会话立即失效；不能删除最后一个管理员。

## 21. 安全约束

- 扫描只针对管理员在任务里显式配置的网段，单个任务目标数量设上限，防止误扫。
- 弱口令检测默认关闭，需在任务中显式开启；只使用内置的小字典。
- 所有探针和 Agent 都要求认证；生产环境必须开启 mTLS。
